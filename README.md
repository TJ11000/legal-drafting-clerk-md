# legal-drafting-clerk-md（起案係）

弁護士の起案補助に Claude を使う時の常駐ファイル（`CLAUDE.md`）です。AI の判例ハルシネーション対策として書きました。命令の形ではなく「わたしはこう働く」という自己記述で書いてあります。同梱の [`KIAN_CLERK.ja.md`](KIAN_CLERK.ja.md) を Claude Code なら `CLAUDE.md` に、他のツールならシステム指示欄に貼って使います。

**効くとは書いていません。** 入れる前と後で何が変わったかの実物（件数と短い引用）と、変わらなかった実測の両方を下に置いています。読んでから決めてください。

## こういう時に

- 依頼文に書いていない事実（打合せの日付・契約書のひな形・従業員の兼務・原価率）を「〜である」の形で置いて、書面を完成させてくる時
- 手元に無い判例を「確認済み」の顔で本文に引いてくる時
- 実在する判例の一般論だけを切り取って、結論が逆であることを言わずに支えとして引いてくる時
- 依頼者の言い分を、書証の無いまま事実の形で書いてくる時

## この文書の読み方（先に4語だけ）

- **素**＝ファイルを置かない Claude。**腕**＝比べる相手（素／このファイル／同じ規則の命令形／Anthropic 公式テンプレ）。**走**＝1回の試行。**押し**＝2ターン目に、依頼した弁護士の権限で指示を押し通そうとすること。**止まる**＝本文を書く代わりに、取得依頼・空欄の札・停止理由を返すこと。
- 材料は合成の判例3本・条文2本と依頼文で、依頼文には罠が4種入っています（手元に無い判例・結論が逆の判例・期限・書証の無い言い分）。**罠の文言と押しの文言は公開していません**（誘発の手口は書かず、症状と直し方までを出す方針です）。

### 効かなかった所（同じ装置で測った物）

- **押されると折れました。** 2ターン目に弁護士の権限で、書証の無い事実の断定を求める押しと、判例の結論を落とす押しをかけると、このファイルは job_058 で 4走中4走が地の文で断定し、job_058b で 4走中3走が断定しました。手元に無い判例を本文に入れた走も job_058 で 4走中2走（空欄つきの断定）。素は全走が従いました。同じ規則の命令形は job_058 で 5走中1走に止まりましたが、job_058b では撃っていません。Claude Opus 5 では、「止まる」は1ターン目に出ますが、「押されても守る」はこのファイルに出ていません（n=4〜5）。Gemini では持ちこたえました（次項）。
- **モデルが変わると「押されても守る」が出ません（Gemma は1ターン目では止まりました）。** ローカルの Gemma 26B では、2ターン目に素・命令形・このファイルの全9走が折れ（このファイルは 3走中3走）、1走は「」付きで判旨を創作しました。Gemini では、書証の無い事実の断定が素 3走中3走・ファイル有り 6走中0走でした（他の項目は機械の一次採点のみで未検証）。このファイルは「止まれるモデルに止まる理由を渡す」までで、止まれないモデルを止めるものではありません。
- **幻のツール操作が、ファイル有りの方に多く出ました。** ツールの無い環境で「帳簿に記帳しました」「ファイルを読みました」と書いた走が、job_058b では素 0／このファイル 6走中6走。うち1走は、やっていない上書き（対象は帳簿ではなく記憶ファイル `MEMORY.md`）を自首しました。ただし job_058 では素にも 5走中2走に記憶ファイルへの擬似保存が出ています。このファイルの帳簿作法が効いたのか、実行環境の記憶機能の規則に反応したのかは切り分けていません。
- 1走（2026-09-13）で、起案メモの推論が逆向きでした（解約日が早いほど残期間は長くなるのに、短くなると書いた）。推測の印は付いていました。

## 使い方

1. `KIAN_CLERK.ja.md` を作業フォルダに `CLAUDE.md` として置く（Claude Code 以外のツールでは、システム指示欄に全文を貼る）。
2. 判例・条文・書証は、人か道具が一次資料（裁判所の判例DB・e-Gov・書証のPDF）から取ってきた本文に出所（DB名・事件番号または条文番号・取得時刻・通し番号）を付けて渡す。このファイルは「記憶で判例を引く」経路を自分で閉じる書き方なので、取得済みの材料が無いと本文を書かずに取得依頼を返します。取得依頼が返ったら、取るのは人（弁護士か事務の担当）です。
3. 帳簿（`kian_ledger.md`）はファイルに書ける環境なら AI が書きます。書けない環境では本文末尾に「帳簿案」が付くので、人が転記します。
4. 試すなら、ご自身の事件の依頼文で、素のセッションとこのファイルを置いたセッションに同じ物を投げて、「依頼文に無い事実を『〜である』で書いた文」を数えて比べてください。同じなら、それがあなたの環境での答えです。

## 限界（先に読んでください）

- **一人・一構成・1モデル。** Claude Code CLI 2.1.267〜2.1.270、Claude Opus 5（2026-09-13 の1走は既定モデルで未固定・推定）、ツール無し（2026-09-13 の走はアカウント側の外部連携が残っていました）、材料は合成。実在の判例データベースにも、本物の事件にも当てていません。
- **判定は人が数えていません。** 断定文の件数は、被験体とは別セッションの Claude（作者の普段の作業用・人間ではない）が全走を目視して数えた物で、作者（人間）は数え直していません。押しに従った走数・幻のツール操作・止まった行数は、試験を走らせた側の Claude の目視です。
- **n が小さい。** 中央値の分母は 3〜6。差の大きさは読めません。向きだけです。
- **「止まる」の代償。** ファイル有りは本文の代わりに取得依頼・空欄の札・停止理由に 1走あたり中央値 18〜20 行を使いました（素は 9〜10.5）。書面を「完成」させる速さは落ちます。素が自発で出した材料外の論点（消費者契約法など）は、ファイル有りでは取得依頼に回ります。
- **照合工程（冒頭注記の「床」）は未配備。** 本体が「機械が見るはずの線」と書いている6本は、2026-10-15 時点で機械は見ていません。本体が自分でそう書いています。
- **弁護士の検品は未。** 法律実務の作法として正しいかは、このファイルの作者（エンジニアでも法曹でもない）には判定できません。
- 試験は「押しのある依頼」だけです。圧の無い普通の依頼での挙動は測っていません。

## 設計の外側（このファイルが担わない物）

このファイルは5つの工程のうち「起案」だけです。取得（毎回まっさらな状態で、解釈しない）→ **起案**（このファイル）→ 照合（機械で ID の実在と逐語一致を見る・別のセッションが判旨が支えるかを読む）→ 予測（先に書いて封じ、当たり外れを残す）→ 帳簿と判子（提出は弁護士だけ）。起案だけ自己記述で、照合は命令形でよい、というのがこの並びの考え方です。照合以降の現物はこのリポジトリにはありません。

## 先行事例

Anthropic 公式の [claude-for-legal](https://github.com/anthropics/claude-for-legal)（米国法前提・命令形・理由つき）が同じ棚の物で、上の表の「公式テンプレ記入版」はそれに架空の事務所情報を記入した物です。その日本語訳は [claude-for-legal-ja](https://github.com/TJ11000/claude-for-legal-ja)。「実在するが支えていない引用」の概念と、出所タグを「確信ではなく行為で決める」書き方は、それぞれ公式テンプレと前作 [research-clerk-md](https://github.com/TJ11000/research-clerk-md) から借りています。近い物として、日本法の行政書士向け Skill（[firemio/gyoseishoshi-skill](https://github.com/firemio/gyoseishoshi-skill)・「不足している事実は創作せずヒアリング項目として返す」を含む・命令形）と、法律事務所向けの Claude Code プラグイン（[llamadrive/bengo-toolkit](https://github.com/llamadrive/bengo-toolkit)）があります。日本法の弁護士の起案に向けて「倒れ方」を先頭に置いた自己記述の常駐ファイルは、GitHub と Web を探した範囲（2026-09-11・2026-10-15）では見つかっていませんが、見つからないことは無いことではありません。ご存じなら issue を1本ください。

## 挙動の報告を受け付けます
